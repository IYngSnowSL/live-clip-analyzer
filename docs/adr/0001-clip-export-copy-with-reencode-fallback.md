# ADR 0001：切片导出默认无损流复制，失败回退重编码

- 状态：accepted
- 日期：2026-09-01

## 背景

导出候选切片有两种经典做法：

1. **无损流复制（`-c copy`）**：不重新编码，直接复制原始码流。
   速度接近文件复制，画质无损；但起点只能对齐到关键帧（I 帧），
   实际切出的片段可能比指定时间**略早**几秒。
2. **重编码精切（`libx264 + aac`）**：重新压缩，起点精确到帧；
   但速度慢一个数量级，且画质有损、体积不可控。

个人工具的场景是：几小时的直播录像要切几十个片段，
如果全部重编码，导出一步可能比分析一步还慢。

## 决策

- 快速模式为**默认**：`-c copy` + `-movflags +faststart`。
- 若源编码无法直接复制（ffmpeg 报错），**自动回退**到 H.264 + AAC 重编码，不中断导出。
- 提供显式 `accurate=true` 精切选项，起点更准，供对时间敏感的单句素材使用。
- 批量导出并发受信号量控制（默认 1，可配置），单个切片失败不影响其余切片。

## 权衡

- 换来的代价：默认模式起点可能比指定时间早若干秒（取决于关键帧间隔）。
  → 对 1~5 分钟的长切片影响可忽略；对几秒的单句素材，建议勾选精切。
- 快速模式要求源与目标的封装/编码兼容；不兼容时靠回退路径兜底，
  代价是用户无法预知某次导出走的是哪条路（可从耗时感知）。

## 后果

- `exporter.py` 中 `export_clip()` 承担两条路径的分派与回退逻辑。
- 导出结果列表需明确标识成功/失败与错误信息，因为批量导出是"部分成功"语义。
- 未来若加入 GPU 加速重编码（NVENC），只影响精切路径，快速路径不受牵连。
