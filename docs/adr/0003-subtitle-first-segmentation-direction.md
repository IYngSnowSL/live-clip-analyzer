# ADR 0003：主功能转向字幕驱动切分（方向性决策）

- 状态：superseded（被 ADR-0006 推翻，2026-09-02：方向废弃，仅存档参考）
- 日期：2026-09-01

## 背景

v0.2.x 的流水线以**视觉场景检测**为切分主轴：画面变化切出 8~30 秒镜头段，
弹幕、ASR、视觉理解只是附着在每个镜头段上的分析素材。这种方式对"画面切换"
敏感，但对"内容在聊什么"不敏感——它切不出"这一段是个完整的故事/话题"。

用户提出新主功能方向：**以完整视频的字幕（ASR 全文）为主要依据**，
整理分析字幕内容，一段一段切出"场景"并截取切片；弹幕、画面降为辅助信息。

## 决策

主功能按以下方向演进（六项子决策已于设计文档
`docs/features/subtitle-first-segmentation.md` §4 全部确认）：

1. **切分主轴**：字幕语义驱动，弹幕 / 画面作为辅助信号。
2. **视觉镜头段去留**：并存两级——现有视觉"镜头段"（scenes 表）保留为底层时间轴，
   字幕"内容段"作为上层结构，暂不替换。
3. **场景语义**：两级都要——"话题段"（几分钟~几十分钟，导航层）+
   "切片友好片段"（30 秒~3 分钟，交付层）。
4. **切分技术路线**：层次化两级（先粗切话题段，再段内细切），
   粗切采用便宜预筛 + LLM 精修以控制成本。
5. **数据模型**：新建 `topic_segments` 表；`scenes` 与 `candidates` 保持不变，
   切片友好片段作为 candidates 的新候选类型落地。
6. **输入画像**：1~4 小时直播录播，内容类型混合（游戏 / 聊天等不限）。

## 权衡

- 换来的代价：全量 ASR 是固定前置成本（时长与金钱）；语义切分需要多级 LLM 调用，
  成本高于现有"每镜头段一次分析"。缓解手段：ASR 结果缓存、块级并发、
  便宜预筛减少 LLM 调用次数。
- 不做"一次推倒重构"而是"并存渐进"：旧链路（弹幕统计、评分、导出）继续可用，
  新链路分阶段接入，任何阶段都可回退。
- 视觉信息保留为独立层级而非删除：纯字幕切分会丢失换游戏、切屏等画面事件，
  并存两级让两类边界互为参照。

## 后果

- 演进顺序（设计文档 §5）：ASR 缓存与字幕整理 → 话题段粗切 →
  段内细切（切片友好片段）→ 辅助信息接入 → UI 与报告跟进。
- 术语表新增"话题段""切片友好片段"；"场景"一词明确专指镜头段，避免歧义。
- 评分体系后续需重排权重：字幕内容为主，弹幕为辅（具体数值待实现阶段确定）。
