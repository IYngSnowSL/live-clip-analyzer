# ADR 0006：推倒重建——自动打轴为唯一核心功能

- 状态：accepted
- 日期：2026-09-02

## 背景

用户重新定义了产品定位（对 ADR-0003 方向的推翻）：

1. 用户是**切片生产者**，软件产物直接用于**切片二创发布**。
2. **唯一核心功能 = 自动打轴**：自动确定每个可切片片段的**精确起止时间与内容说明**
   （"确认片段内容和长度"）。
3. 此前的多层设计（视觉场景 → 话题段 → 评分 → 长切片/单句候选）被判为**臃肿**，
   要求推倒重来。

## 决策

### 全新流水线（极简，一切为打轴服务）

```
① ffprobe 视频信息
② 提取音频 → ASR 全量转写（asr.json 缓存复用）
③ LLM 分窗分析字幕 → 找内容点并初步打轴（标题/理由/评分/起止时间）
④ 合并相邻内容点 + 长度约束（目标 1~3 分钟，硬上限 10 分钟）
⑤ ffmpeg silencedetect 静音点精修每个轴的起止
⑥ 保存 axles → 页面轴列表 + CSV 导出 + 切片导出
```

### 打轴规格（用户拍板）

| 项 | 决定 |
|---|---|
| 目标长度 | 1~3 分钟（自然边界优先），硬上限 10 分钟 |
| 精度 | 句子级打底 + **静音点精修**（silencedetect） |
| 每场输出量 | 大量候选（默认最多 100），按评分排序，人工挑选 |
| 输出形态 | 页面时间列表（点击跳视频预览）+ **CSV 导出**（对照剪辑软件打轴） |

### 数据模型

- 保留 `tasks`；新增 `axles` 表作为**唯一产物表**（含复核字段）。
- 废弃 scenes / topic_segments / candidates 表及其全部代码路径。

### 删除的旧功能（判为臃肿）

- 视觉场景检测与 8~30 秒时间轴
- 画面理解（视觉模型调用）
- 弹幕统计（热度/情绪/关键词）
- 话题段（粗切导航层）
- 综合加权评分（LLM 直接给每轴评分）
- 中英双语报告（输出改为中文轴清单 + CSV）

### 保留的旧能力

- 任务管理、ASR（核心前置）、AI 门面（LLM 能力接口）
- ffmpeg 切片导出（快切/精切——切片生产者的刚需）
- 视频预览跳转、文件浏览、配置页

## 权衡

- 舍弃视觉/弹幕信号换取**流程极简与成本下降**：一次任务只调 LLM（分窗找内容点），
  不再每场景调视觉+LLM 两次。若未来需要，视觉/弹幕可作为可选增强加回
  （AI 门面已预留 describe_images 能力）。
- 打轴质量完全依赖 LLM 对字幕的理解，ASR 质量成为关键前置。

## 后果

- `docs/features/subtitle-first-segmentation.md` 的旧设计作废，以本文为准。
- 旧任务数据（scenes/topics/candidates 表）不再被读取；数据库新任务只写 axles。
- 评分从"加权公式"变为"LLM 直接评分"，阈值与权重配置全部移除。
