# ADR 0002：配置四级优先级，密钥不进入 git

- 状态：accepted
- 日期：2026-09-01

## 背景

v0.2.0 及更早版本只有一个 `config.yaml`，且该文件被 git 追踪。
`.gitignore` 中虽有"把真实 key 放 `config.local.yaml`"的注释，但代码从未实现读取它。
这意味着：只要把真实 API key 写进 `config.yaml`，下一次提交就会把它推上 GitHub。

同时，个人开发机上通常已有现成的环境变量（如 `DEEPSEEK_API_KEY`），
更自然的做法是让程序直接读环境变量，而不是再复制一份进配置文件。

## 决策

配置读取顺序固定为四级，**后者覆盖前者**：

1. 内置 `DEFAULTS`（代码内默认值，保证配置残缺也能启动）
2. `config.yaml`（提交到 git，只放占位符 `sk-xxxx` 等）
3. `config.local.yaml`（git 忽略，存放本机真实 key，可选）
4. 环境变量 `LCA_*`（优先级最高，适合临时切换服务）

环境变量映射：`LCA_BASE_URL` / `LCA_API_KEY` / `LCA_VISION_MODEL` /
`LCA_LLM_MODEL` / `LCA_ASR_MODEL`，分别对应 `ai.*` 配置项。

## 权衡

- 增加了一个"配置文件不存在时该看哪里"的心智负担；
  但优先级规则固定且写在 `config.py` 文档字符串里，容易排查。
- 环境变量只在进程启动时读取一次，运行中改环境变量不会热生效。
  → 个人工具可接受；代价是用户可能困惑"为什么改了不生效"，README 已说明。

## 后果

- 密钥泄漏风险降为：只在"把真 key 写进 config.yaml 且忘记清理就提交"时发生。
- 未来接入更多外部服务（ASR / 视觉 / 文档识别）时，沿用同一套 `LCA_*` 前缀即可。
- 测试可用环境变量注入配置，无需碰真实 config 文件。
